# blueprint-arcade

Source of the **Arcade** format (`format.arcade`), for making and playing retro games together. An arcade has:

- a shelf of games, each a JavaScript cartridge that anyone can edit beside a live preview;
- a small retro engine;
- a chiptune composer whose tunes play in games and export as WAV or MIDI;
- shared high scores;
- per-player key layouts.

It is stocked with starters to adapt: Invaders, Rocks (vector asteroids), Blocks (falling blocks), Bricks, and three classroom games in the BBC Micro / RM Nimbus tradition (Number Gulper, Teletext Tables, Dark Room). The user guide, engine reference and RPC reference is [`src/README.md`](src/README.md). It ships inside the gadget, and the Code tab shows it as the Reference panel.

## Layout

| Path | What |
| --- | --- |
| `src/engine/` | The engine. `index.js` runs a cartridge and builds its `a` API. `gfx.js` is a palette-indexed framebuffer with an 8×8 font, sprites, polygons and palettes/modes. `input.js` handles actions and layouts. `audio.js` handles Web Audio playback. `helpers.js` holds RNG, maths, collision, timers, particles, grids, the falling-block well and menus. `assets.js` has built-in sprites and vector shapes. `teletext.js` is Mode 7. `edu.js` is the classroom kit |
| `src/shared/music.js` | MML parser, pure-JS chip synth, sound-effect presets, BBC `SOUND`, WAV and MIDI encoders. Shared by client and server |
| `src/shared/font8x8.js` | Generated by `scripts/extract-font.mjs` from the public-domain Linux console VGA 8×8 font |
| `src/cartridges/` | Starter games as `<id>.cart.js` (stored as text in each arcade), with `registry.js` and `sources.js` |
| `src/tunes/starter.js` | Starter tunes |
| `src/core/` | Rules (`arcade.js`) and persistence/fan-out (`store.js`) |
| `src/server/index.js` | The `Gadget` Durable Object and `ExportHandler` (Markdown, all code, WAV/MIDI per tune) |
| `src/client/` | Plain-DOM UI: `app.js` (shelf, play, code, music, controls), `player.js` (runs a cartridge on a canvas), `composer.js`, `styles.js`, `main.js` (connection and recovery) |
| `harness/` | Side-by-side players (`?names=Alice,Bob`) running the real client over the real rules |
| `e2e/harness.test.mjs` | Playwright over the harness |
| `test/engine/` | Headless cartridge runs (every starter under random input, scripted play-throughs), music |

## Commands

Run these from this directory, with node from fnm (`fnm use v24.21.0`).

```sh
pnpm test:run                            # node tests (engine, music, cartridges, rules) + workerd tests (Durable Object, exports)
pnpm pack:gadget                         # build dist/, write formats/arcade.gadget (bumps revision on change)
node scripts/build.mjs && pnpm test:e2e  # harness end-to-end
pnpm harness                             # serve the harness at http://127.0.0.1:8790/harness/
```

The `test` task run by `pnpm check` rebuilds `dist/` and fails when `formats/arcade.gadget` is stale. **Run `pack:gadget` and commit the archive with every source change.** Never change `blueprintId`.

## Design notes

- **Games are data, not gadget files.** Each arcade stores its games' source in Durable Object storage (`g:<id>`, up to 100 KB each), so players and the agent can change games without rebuilding the gadget. The client imports a game as a `data:` module: the gadget CSP allows `script-src data:` but not `eval`. A syntax error is located by parsing the source again as an inline module script, whose error event carries the line.
- **The engine is headless.** It draws into a byte-per-pixel framebuffer, which the player copies to a canvas. The tests can therefore run every starter for thousands of frames in Node.
- **One synth for everything.** Games, the composer and the WAV export all render through `renderSong`/`renderSfx`, so an exported tune sounds as it did in the browser. The sandboxed iframe cannot download files, so audio leaves through the platform's Export menu.
- **Keys.** Games read actions. Players choose a layout, or "auto" for the game's own, and can rebind actions. Settings are stored per account (`p:<userId>`). Escape is never bound, because the platform uses it to leave full screen.
- **Concurrent edits.** `saveGame`/`saveTune` take `baseVersion` and refuse a stale save instead of overwriting it.
- **Trust.** As with every format here, the server takes `by` from the caller. Game code runs only in viewers' sandboxed frames (no network), and is written by people who can edit the arcade anyway.

## Adaptable gadget checks

The packed format ships readable client/server entries, prebuilt libraries, and a bounded
`describeGadget()` contract. Evals live in `src/evals.mjs` and are never packed.

Run the archive integration checks with `node --test scripts/blueprint-adapt.test.ts` from
the repository root. They run every RPC example and every reference eval against the
shipped archive, including the real assembled client in Chromium. Connector-backed formats
use deterministic fixtures, not live accounts.

Reference validation (2026-10-01): 3/3 evals pass against the packed archive; all
`describeGadget()` examples run. Package unit/server suites pass. Shared extension and
build checks, scoped tooling lint, and script type checks pass. Signed-in Workshop
smoke tests have not been run.

Model evals: `litellm_proxy/deepseek/deepseek-v4-flash` passed 3/3 on 2026-10-01
(one run per eval, with operator authorization to send gadget code).
