Delivery status · Deployed alpha

The alpha is live. Integration comes next.

The direction is locked: standards-based models, portable Postgres, PostgREST reads, explicit commands and a small gateway. The old Projects-focused runtime remains separate while the new service is qualified.

Implemented, with local and live evidence

  • Complete pinned Schema.org 30.1 catalogue: 3,026 terms, provenance, aliases, multiple inheritance and term status.
  • Explicit profiles, validation, JSON Schema, restricted JSON-LD and versioned mapping fixtures.
  • Work and messaging modules, plus a third independently published inventory module without core edits.
  • Scoped service credentials, ES256 gateway tokens, runtime-role isolation, transactional history, revision checks and idempotency.
  • Module publication, additive upgrades, immutable migration checksums and rollback on installation failure.
  • REST, a TypeScript client, authorised SSE hints, journal catch-up and bounded consistent snapshots.
  • A runnable Docker Compose reference stack and a local logical restore rehearsal.
  • Both product-site editions are live, with docs and API on the homeserver through Cloudflare Tunnel.

Next: adapt and explore

Two detailed blueprint plans cover a Work Board and Report, with Jira/Linear mapping examples, and a generic Records Explorer. Both depend on the same live OS credential and approval integration. Existing project blueprints continue to use the legacy backend.

Next: qualify and integrate

A ten-minute local test sustained 59.73 successful commands per second with zero request errors; 160 scheduled attempts were skipped by the generator capacity cap. Local listener recovery and revocation tests pass. Extend contention, full-process recovery and homeserver workload testing; these measurements are not a service-level commitment. Complete real cloudflare-os enrollment, credential brokerage and exact-intent approvals. Validate Worker HTTP and optional Hyperdrive/VPC paths in the target account. Local tests and benchmarks are evidence for this workload, not a service-level commitment.

Before production

Hosting is selected; operational ownership, capacity limits, key rotation, retention and erasure, PITR, cross-cluster recovery and a staged data cutover remain explicit gates. No existing production datastore has been migrated by this implementation.

Separate future work

Rich collaborative documents, attachments, visual model editing, arbitrary database federation and complete compatibility with Jira/Linear, Slack/Teams or Notion/Confluence are not part of the current alpha.
