Local alpha HTTP contract

Ordinary HTTP. Meaningful commands.

The gateway serves approved collection reads and explicit commands. Module IDs and API majors select registered contracts; callers cannot select arbitrary SQL or database schemas.

The routes below are implemented. Obtain local datastore IDs and scoped credentials using the getting-started guide. Placeholders are not credentials.

Read records

GET /v1/datastores/{id}/modules/work/v1/records?limit=20
Authorization: Bearer {scoped-service-key}

Supported collection parameters are entity, id, limit, after and format=jsonld. The alpha does not expose PostgREST’s complete filtering language. Messaging uses /modules/messaging/v1/records.

Send commands

POST /v1/datastores/{id}/modules/work/v1/rpc/work.create
Authorization: Bearer {scoped-service-key}
Content-Type: application/json
Idempotency-Key: create-work-001

{"title":"Build the customer portal","status":"open"}
POST /v1/datastores/{id}/modules/messaging/v1/rpc/messaging.send
Authorization: Bearer {scoped-service-key}
Content-Type: application/json
Idempotency-Key: send-message-001

{"channel":"general","body":"The shared model is ready."}

The work states are open, active and done. Updates use work.update or messaging.edit, include the record ID, and supply If-Match with the current revision. Missing revisions return 428; stale revisions return 412. Reusing an idempotency key with a different command input returns 409.

Models and discovery

GET /v1/models/work/profile
GET /v1/models/work/schema/work_item
GET /v1/vocabulary/schemaorg/terms/Project
GET /v1/openapi.json
GET /v1/datastores/{id}/describe

Vocabulary and profile definitions are public semantic metadata. Datastore descriptions and record data require authority. The repository contains a working TypeScript client; no public SDK package release is implied. Jira/Linear or Slack/Matrix compatibility would remain independent, tested adapter work.

Changes and snapshots

Use /v1/datastores/{id}/changes?after=0&limit=100 to pull journal entries and /events for authorised SSE hints. Use /modules/work/v1/snapshot for a bounded consistent snapshot. Retain the returned permission epoch; an epoch mismatch requires resetting cached data. Large snapshots fail explicitly rather than silently returning an incomplete dataset. Notifications carry hints; clients must reconcile through the journal after missed events.

Errors use application/problem+json. Retry and cursor handling are available in the local client; production retention, erasure and recovery policy remain unfinished.
