Runnable local alpha

Start with a shared datastore.

Use Node 24.19+, pnpm and Docker Compose from the repository root. This starts the new service alongside the preserved earlier implementation.

1. Install and prepare

pnpm install --filter @records/service...
pnpm --filter @records/service dev:prepare

Preparation creates local keys, datastore IDs and configuration under packages/records-service/.eval/. It retains existing configuration on repeat runs. The files are credentials for your local instance; the commands do not print them.

2. Start the stack

docker compose --env-file packages/records-service/.eval/compose.env \
  -f packages/records-service/compose.yaml up -d
curl --fail http://127.0.0.1:8788/healthz
curl --fail http://127.0.0.1:8788/v1/models/work/profile
curl --fail http://127.0.0.1:8788/v1/vocabulary/schemaorg/terms/Project

Wait for initialization and health checks before calling the API. Only the gateway is exposed on localhost; Postgres and PostgREST stay on the private Compose network.

3. Create a work item

This Node example reads the generated local credential without displaying it. Run from the repository root. It prints the command result, which contains the created record and revision.

node --input-type=module <<'JS'
import { readFile } from 'node:fs/promises';
const config = JSON.parse(await readFile(
  'packages/records-service/.eval/client.json', 'utf8'));
const url = `${config.baseUrl}/v1/datastores/${config.work.datastoreId}`
  + '/modules/work/v1/rpc/work.create';
const response = await fetch(url, {
  method: 'POST',
  headers: {
    authorization: `Bearer ${config.work.key}`,
    'content-type': 'application/json',
    'idempotency-key': 'getting-started-work-001'
  },
  body: JSON.stringify({title: 'Build our own workflow', status: 'open'})
});
if (!response.ok) throw new Error(`Records returned ${response.status}`);
console.log(await response.json());
JS

Repeating this exact command returns the same committed result. To create a different item, use a new idempotency key. Messaging uses its own generated datastore/key and /modules/messaging/v1/rpc/messaging.send with {"channel":"general","body":"Hello"}.

4. Explore and stop

Read /modules/work/v1/records with the same credential, inspect the HTTP API, or review the independently publishable inventory module.

docker compose --env-file packages/records-service/.eval/compose.env \
  -f packages/records-service/compose.yaml down

The named database volume is retained. The website’s interactive explorer is a separate illustrative demo. This local setup does not configure production hosting or complete cloudflare-os enrollment.
