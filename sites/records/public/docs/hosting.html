Deployed alpha and portable reference stack

Postgres wherever you need it.

The implemented stack uses ordinary Postgres and upstream PostgREST, with a Node gateway and change relay. Neon is optional. The website remains static and can run independently.

Current deployment

The website and API are live at records.surprisingly.ltd. Cloudflared reaches the Node gateway on the homeserver. Postgres and PostgREST run beside it on private Docker networks, with no public database ports. The database has persistent storage. Pinned images, Compose and checksummed releases describe this deployment; it uses neither Neon nor Hyperdrive.

Run the local reference topology

Docker Compose instructions → The stack uses pinned images, a persistent database volume, private service networking, health checks and a localhost gateway port. Generated credentials stay in the local ignored .eval directory.

Connecting from Cloudflare

REST clients need an authenticated HTTP route to the gateway. Trusted Worker SQL access through Hyperdrive and private access through Workers VPC are planned deployment paths, not qualified integrations in this alpha. Direct database connections remain necessary for listeners and migrations.

Recovery evidence

A local logical backup has been restored to a separate disposable database and checked against source table contents, journal and migration ledger. The rehearsal script is repeatable on a quiescent local stack. This does not establish production point-in-time recovery, cross-cluster role restoration or a recovery-time objective.

Production gates

The homeserver is selected for the alpha. Before business data, establish operational ownership and off-host backups. Establish encryption, secret rotation, backup retention, recovery objectives, monitored limits, redaction and erasure policy. Validate production traffic and multi-datastore contention. Managed Postgres and self-hosted Postgres are both possible; operating responsibility remains explicit.
