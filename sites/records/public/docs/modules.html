Implemented publication foundation

Model the domain. Publish the contract.

A module is a reviewed developer package: semantic profile, scopes, commands and checksummed SQL migrations. It is privileged deployment, not an end-user SQL sandbox.

Three working examples

Work items have title, status, description and extensions. Messages have channel, body and extensions. The separately publishable inventory module has assets with label and serial, using a custom ontology without Schema.org. Its command is inventory.register; publication needs no core domain branch.

Publish, then provision

The publisher validates names, scopes, profiles, handler signatures and migration checksums. It holds an installation lock, applies transactional migrations, records the release and requests a PostgREST schema reload. Repeat publication is safe; incompatible same-major changes and edits to applied migrations fail. A failed SQL migration rolls back registration and schema changes.

Publication creates no datastore and grants no authority. Provisioning is a separate operator action. The local administration scripts live under packages/records-service/scripts/. Use manage.ts publish with a reviewed module directory and a dedicated migration connection; connection secrets belong in the environment.

Separate meaning from storage

Profiles define terms and constraints. Versioned mapping helpers translate columns, identifiers and enum values; tests map two physical layouts to one model. Executable SQL must enforce the same rules and return the shared projection contract. Automatic mapping of arbitrary databases is not implemented.

Core responsibilities

Identity, memberships, bindings, credentials, datastore isolation, revisions, idempotency, ordered history and change delivery remain shared. Product-specific identifiers and compatibility behaviour belong in adapters: Jira or Linear for work, Slack or Matrix for messaging, Notion or Confluence for documents.

Before broader publication

Automated public-contract probes, package distribution, richer compatibility analysis and production release governance remain planned. SQL authors must review resource use and permissions. No complete third-party workflow parity is claimed.
