Proposed architecture · September 2026

Meaning first.
Implementations follow.

A project is a project before any particular tool gives it a screen. Records puts an open, shared model at the centre, with databases, apps and SDKs mapped to it.

The local alpha includes the complete pinned Schema.org 30.1 catalogue: 3,026 terms from 3,259 graph nodes, with provenance and checksums. Work and messaging profiles execute against the new service. Richer project/channel profiles remain examples.

Use it. Extend it. Start fresh.

The complete pinned vocabulary is available as a catalogue: types, properties, relationships and their provenance. Well-modelled application profiles add the constraints and commands required by real software. Choose one, extend it with your own namespaced concepts, or start with an entirely custom model.

Catalogue coverage is different from executable profile coverage. Loading every term does not mean that every industry workflow has been designed or tested.

Four layers, separate responsibilities

LayerWhat it means
VocabularyShared terms with stable identifiers, such as schema:Project and schema:name.
Application profileYour chosen concepts, relationships, validation rules and domain commands.
Storage mappingHow model fields and identities correspond to tables, columns, views and writes.
App or SDKA particular way to read or act on that model. Independently replaceable.

An open project model

Schema.org defines Project as a kind of Organization. A work-tracking profile can build on it and introduce its own WorkItem, status and transition concepts. Those additions belong in the profile’s namespace, not in Schema.org’s.

{
  "@context": {
    "schema": "https://schema.org/",
    "work": "https://example.org/work/"
  },
  "@id": "urn:uuid:cc7a197e-3307-4cba-9fb0-5f53b093a018",
  "@type": "schema:Project",
  "schema:name": "Customer portal",
  "work:stage": "discovery"
}

Illustrative JSON-LD, with a placeholder extension namespace; this compact-context example is not accepted by the alpha importer. The implemented importer/exporter uses expanded IRIs and never fetches remote contexts. The application profile would define work:stage and its allowed values. Plain JSON remains available to ordinary REST clients; JSON-LD supplies explicit semantic identifiers for interchange.

Map a database to the model

Database A                    Open model                 Database B
initiatives.label      ↔      schema:name        ↔       projects.title
initiatives.phase      ↔      work:stage         ↔       projects.state

Mappings also define identifiers, enum translation, missing values, cardinality and supported write operations. Two physical schemas can implement the same public model. This needs reviewed mappings and tests; matching field names alone is not enough.

Initially, writable mappings stay inside the supported Postgres transaction and history boundary. Importing existing data and exposing reviewed views are in scope. Automatically federating arbitrary remote databases is not.

Let someone else build the adapter

An independent developer could build an SDK that accepts Jira- or Linear-shaped objects and translates them to the open work model. Another could map Slack or Matrix messages, or Notion and Confluence documents, to their respective open models. That SDK owns the translation and its compatibility promises. Records works without it, and the Records team does not need to maintain it.

The same principle applies to a messaging client, a wiki or a specialist industry app. An app expresses one interpretation of the shared model; it does not own the underlying meaning.

Standards are a foundation, not a universal truth

Schema.org is an extensible shared vocabulary, not a complete ontology of nature. Records should preserve where concepts come from, how they are defined and which version a mapping uses. Domain experts can refine or replace a model without pretending that one vendor’s conventions are inevitable.

Open meaning also does not imply public data. Grants, identity, database constraints and tested isolation govern access. A standard vocabulary cannot substitute for those controls.
